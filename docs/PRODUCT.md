# Job Hunter — продуктовая рамка (analyst-grade)

> Единый источник правды: зачем сервис, для кого, какой результат, что ограничивает разработку.
> Обновляется при изменениях. Дата: 2026-10-12.

## 1. Проблема и JTBD

Поиск работы в 2026: площадки шумят («вечные» вакансии, перепосты, зонтики-пулы, бот-фильтры), API закрываются (hh, апрель 2026), кандидат тратит время на ручную фильтрацию и теряет follow-up'ы.

**Job to be done:** «Когда появляется подходящая мне вакансия, я хочу видеть её **оценённой против моего профиля с объяснением** — за 5–10 минут утра, — чтобы точечно откликаться и вести воронку без потерь.»

## 2. Целевой результат (outcome), а не фичи

| Результат | Как измерим |
|---|---|
| Утренний обзор вакансий ≤ 10 минут вместо часа на 4 сайтах | самозамер за неделю |
| Релевантность дайджеста: доля LLM-триажа «keep», с которыми пользователь согласен | ручная сверка N=20, цель ≥ 80% |
| Полнота: релевантные новые вакансии/день по активным источникам | счётчик в БД |
| Воронка: 100% откликов зафиксированы со статусом и датой | дисциплина использования /pipeline |
| Ноль утечек наружу (профиль, резюме, отклики) | код-ревью + политика доступа |

## 3. Ограничения, влияющие на разработку (реестр)

| # | Ограничение | Влияние на «что делаем» | Влияние на «как делаем» | Источник |
|---|---|---|---|---|
| C1 | **Приватность**: профиль/резюме/история не покидают машину; deny-политика для агента (`.env`, `data/*.{pdf,docx,doc}`, внешние пути) | нет облачных SaaS-фич, нет телеметрии наружу; SecretStr; gitignore на персональное | любая фича проектируется local-first | решение владельца 12.10 |
| C2 | **Белые источники**: только официальные API / открытые данные / RSS; скрапинг против ToS — запрещён | hh через RSS пока нет OAuth; LinkedIn/Indeed сознательно вне; LinkedIn — только M4+варианты | каждый источник — датированная эмпирическая проверка в docs/SOURCES.md | решение 12.10 |
| C3 | **Ресурсы MacBook**: ≤1 модель LLM в памяти, батчи, явная выгрузка, деградация по свободной RAM | LLM — точечно (триаж/экстракция/вердикт), не фоновым потоком | §7.1 в коде: pick_model по psutil, keep_alive=0, num_ctx-кап, чужие модели не трогаем | требование владельца 12.10 |
| C4 | **Гибрид действий**: автоматика = поиск/анализ/наблюдение; ручное = отправка отклика и финал резюме | нет авто-отклика; есть «отметка ручного отклика» с датой | воронка построена вокруг ручного отклика | решение 12.10 |
| C5 | **Single-user, localhost** | без auth/multi-user/мобильного доступа (пока) | FastAPI на 127.0.0.1, без DnD/SPA-излишеств | интервью 12.10 |
| C6 | **Инженерная планка**: Python 3.13+uv; только permissive-лицензии у зависимостей; ruff+mypy strict+pytest зелёные перед релизом | блокирует добавление сомнительных библиотек | гейты в AGENTS.md | конвенция проекта |
| C7 | **Не изобретать велосипеды**: сначала поиск зрелых решений (PyPI/GitHub/Хабр) с проверкой лицензии/безопасности | reюз: feedparser, rapidfuzz, psutil, pypdf, FastAPI/Jinja, APScheduler… | запись выбора в PLAN.md | требование владельца 12.10 |
| C8 | **Пока сервис сырой (до v1.0.0)**: данные можно чистить целиком без сохранения (пользователь не использует по-настоящему) | смелые схлопывания схем/данных допустимы | миграции всё равно пишем (привычка), но wipe разрешён | владелец, 12.10 |

## 4. Допущения и риски

| Риск | Вероятность | Митигация |
|---|---|---|
| hh закроет RSS вслед за API | средняя | OAuth-коннектор готов (ожидает одобрения заявки); есть trudvsem/SuperJob/Habr |
| SuperJob введёт платность/лимиты | низкая | бесплатных ключевых источников 4 (реестр) |
| trudvsem скуден по IT-лидерству | высокая (уже так) | источник — один из четырёх, скоринг шум чистит |
| Локальные модели неточны/теv1 на русском слабее | средняя | fail-open триаж, порог 0.5, LLM — поверх rules, не замена; метрика согласия выше |
| Владелец не ведёт воронку дисциплинно | :) | UI делает фиксацию отклика одним кликом |

## 5. Не-цели (осознанно НЕ делаем)

- массовые авто-отклики и «взлом» антибота; обход капчи/прокси-фермы;
- SaaS/мультитенант/аккаунты; хостинг наружу;
- запись данных на площадки (публикация резюме и т.п.) — до отдельного решения (M4+);
- браузерная автоматизация LinkedIn/Indeed.

## 8. Релизная политика

**SemVer на тегах**: пока 0.x.y: minor (y→y+1) = этапный результат с демо; patch = фиксы/полировка между этапами; 1.0.0 — когда M4 и неделя реального ежедневного использования без критичных правок. История — в [CHANGELOG.md](../CHANGELOG.md) (Keep a Changelog). Публикация: аннотированные git-теги `v*` в репозитории; GitHub Releases — после установки `gh` или вручную из тега веб-интерфейсом.
