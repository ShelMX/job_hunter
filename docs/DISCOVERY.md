# Discovery — картина мира поиска работы и назначение сервиса

> Дата: 2026-10-12. Статус: на обсуждении владельцу. Источники указаны у каждого блока.
> Этот документ — то, что нужно было сделать до кода. Выправляет назначение, сценарии и рамку принятия решений.

## 1. Для чего сервис (переформулировано доказательно)

Владелец ищет работу и хочет: **меньше времени на поиск или больше качественных вариантов за то же время.**
Операционализация: сократить время на обнаружение и оценку вакансий (рутина) и повысить долю «качественных» попаданий в отклики, не беря на себя то, что решает человек/рынок (собеседования, оффер, позиционирование).

## 2. Картина мира (что доказано источниками)

### 2.1 Каналы и их реальная доля в наймах
| Канал | Данные | Источник |
|---|---|---|
| **Рефералы/рекомендации** | 5–7% заявок → **30–50% наймов** (Jobvite, LinkedIn Talent Solutions); среди малого бизнеса 2% заявок → 11% наймов (CareerPlug, 10 млн заявок, 2024); time-to-hire 29 дней vs 39–42 с бордов | Jobvite Recruiting Benchmark; social-hire; insidetrackjobs |
| Джоб-борды | доминируют по объёму заявок, не по доле наймов | studojo 2026 (синтез Ashby/Gem/CareerPlug) |
| Массовые авто-отклики (агенты) | ~4.6% отклик→приглашение (НейроКарьера: 13 приглашений / 280 откликов за 14 дней); заявка «63% получили приглашение за неделю» — маркетинг их методики, см. их /metodika | neurocareer.ru (нашёлся в ресёрче, RU-аналог) |

**Вывод:** борды — это «широкая сеть», рефералы — «точечный выстрел» с максимальной конверсией. Сервис не может выдать реферала, но может держать **контур наблюдения за целевыми компаниями + трек аутрича** (см. §5, F2).

### 2.2 Скорость и свежесть
Отклик в первые 24–72 часа заметно увеличивает шанс показа рекрутеру (рекрутеры идут по дате; у зрелых вакансий сотни заявок первой волны). Наша история наблюдений (`first_seen`) + планировщик 2×день уже ловят это преимущество. Усиление: раз в 3–4 часа для watchlist-контура.

### 2.3 Воронка и её конверсии (метод консультантов)
Ступени: **отклик → просмотр → приглашение → собеседование → оффер**. Консультантская практика (netwrk.ru, карьерный специалист Дарья Петриченко, 07.2026):
1. нечёткая цель (нет ответа на «какая роль / какой уровень / какая вилка») — главный тормоз;
2. резюме «под всех» без результатов в цифрах и ключевых слов вакансии (ATS!);
3. ошибки стратегии откликов (ширина, каналы: нетворкинг/прямые обращения/сообщества выпадают);
4. собеседования (подача опыта, переходы, сложные вопросы, переговоры);
5. **нет аналитики воронки** — неизвестно, где ломается.

Метрики, которые консультанты просят отслеживать: релевантные отклики/неделю; конверсии отклик→просмотр→приглашение→интервью→финал; качество офферов. Рост показателей = стратегия работает.

### 2.4 Что в этом мире делают ИИ
По той же статье и рынку: ИИ берёт **рутину** — адаптацию резюме под вакансию, ключевые слова, сопроводительное письмо, сравнение профиля с требованиями, подсветка пробелов; человек — цель, решения, интервью, переговоры. Это ровно наша гибридная граница (C4).

## 3. «Качественный вариант» — операционализация

Вакансия качественна для кандидата, если одновременно:
1. **Соответствие цели**: роль/уровень/вилка/формат/локация в профиле (у нас: правила + LLM fit).
2. **Живость вакансии**: свежая, не «вечная», не перепост-пул (у нас: история наблюдений + кластеры).
3. **Качество работодателя**: не скрыт, нет паттерна вечных пулов (у нас: employer_stats; впереди — внешние сигналы).
4. **Вероятность ответа**: источники/работодатели с живой реакцией, «сбор резюме» без ответа — понижение (у нас частично: нужна метрика отклик→ответ самого владельца для калибровки).
5. **Прозрачность**: вилка указана, требования конкретны (частично: экстрактор LLM это читает).

| Часть процесса | Сейчас | v0.4+ (предложение) | Вне скоупа |
|---|---|---|---|
| Обнаружение (источники, пресеты, свежесть) | ✅ | + watchlist целевых компаний (Greenhouse/Lever/hh-работодатели), чаще (3–4 ч) | — |
| Семантический отсев шума (триаж) | ✅ | калибровка порога по вашим согласиям/несогласиям | — |
| Оценка с объяснением | ✅ | причины отказов от вас → обучение весов (scoring.yaml) | — |
| Воронка CRM | базово ✅ | follow-up напоминания (X дней без ответа), конверсии по ступеням (числа из §2.3) | — |
| Адаптация материалов (резюме/письмо под вакансию) | ❌ | LLM-черновик под конкретную вакансию; вы проверяете и шлёте вручную (C4) | автоотправка |
| Реферальный/прямой контур | ❌ | трек контактов и аутрич-напоминания в воронке; сервис сам не «добывает» людей | сама связь |
| Собеседования/переговоры | ❌ | чит-листы под вакансию (LLM, из требований) — опционально v0.5 | тренинг/коучинг |
| Диагностика «где ломается» | ❌ | конверсии по ступеням из статусов воронки + еженедельная сводка | карьерная диагностика глубокая |

## 5. Сценарии использования (happy flows + ключевые альтернативные)

- **F1 Утренний дайджест** (основной, есть): планировщик → свежее → триаж → вы 5–10 минут → ✨/📨/🙈.
- **F2 «Вакансия-мечта» алерт**: watchlist-работодатели (например, 10 компаний-мечты) мониторятся чаще (3–4 ч), свежая подходящая → заметный бейдж «🔥 fresh». *Скорость — реальное преимущество (§2.2).*
- **F3 Подготовка отклика (гибрид)**: в карточке кнопка «Подготовить отклик» → LLM драфтит короткое письмо под требования + подсказывает фокус резюме → вы правите и **отправляете вручную на сайте** → статус 📨 фиксируется.
- **F4 Недельный обзор**: страница `/metrics`: конверсии по ступеням, средний срок ответа по источникам, «что не работает» (подсказки по §2.3).
- **F5 Просмотр без профиля/LLM** (альтернативный, есть): rules-only, `--no-llm`.
- **F6 Полный офлайн-контур** (альтернативный): площадки лежат → показываем кэш + пометка «данные устарели N ч».

## 6. Архитектурные вопросы (влияют на надёжность/устойчивость/безопасность/вид)

| Вопрос | Текущий ответ | Меняем что-то? |
|---|---|---|
| Надёжность данных (потеря БД) | SQLite-файл; миграции; в кэше LLM всё пересчитываемо | добавить ротационный бэкап `data/backups/` (в задачи v0.4) |
| Устойчивость к сбоям источников/LLM | изоляция ошибок источника; LLM fail-open | достаточно; добавить маркер «данные устарели» в UI |
| Доступность | локально, один процесс web+scheduler | норм; `--no-scheduler` для ручного |
| Безопасность | SecretStr, `.env` deny, перс.данные deny, repo-hygiene | + Keychain опционально (предложено ранее) |
| Внешний вид | server-rendered Jinja, тёмная тема | достаточно до v1.0; HTMX/DnD — по запросу после живого использования |
| Адаптивность источников | плагины + entry points + `type: rss` | норм; M4 добавляет white-источники |

| F3 Адаптация материалов | **Да, в v0.4, с обязательным де-LLM постпроцессингом**: черновик письма/подсказки резюме проходят слой «очеловечивания» — убрать AI-маркеры (канцелярит, однотипные длины, тире-шаблоны, «важно отметить»…), добавить конкретику из профиля, варьировать ритм; есть OSS-чекеры/списки маркеров — исследовать перед реализацией (см. §7.5) |

| hh-отклики | **Полуавтоматика**: сервис готовит, владелец подтверждает и шлёт; с лимитами hh; массовая автоотправка — отвергнута (риск бана, контрпример: НейроКарьера 60/день) |

### 7.5 Де-LLM постпроцессинг писем (требование к F3)
Черновик «сырой» LLM читается роботно и палится чекерами. Требование: финальный текст должен (а) содержать конкретные факты из профиля/вакансии, (б) не иметь шаблонных маркеров, (в) по стилю быть коротким деловым письмом человека. Реализация: правила-чистка известных маркеров + второй LLM-проход «перепиши живее, короче, конкретнее» + опциональная проверка OSS-детектором. Исследовать перед кодом: существующие списки маркеров/de-slop утилиты (reЮз-первый принцип, C7).

1. Watchlist целевых компаний (F2) — нужен ли? Если да — список компаний с вас.
2. Адаптация материалов (F3) — граница гибрида: драфтим письмо/подсказки?
3. Метрики воронки + follow-up (F4) — в какой релиз?
4. hh-отклики: подтвердить полуавтоматику (генерим + вы подтверждаете) vs полностью вручную; (контекст: у НейроКарьеры 60 автооткликов/день — риск бана аккаунта реален, hh официально борется).

## 8. Договорённости по процессу (выученный урок)

До написания кода любой фичи: (1) сценарий в DISCOVERY/UI_SCENARIOS; (2) ограничение в PRODUCT.md если трогает C1–C8; (3) риск/митигация; (4) критерий приёмки; (5) потом реализация с тестами. Назад-совместимость: существующий код остаётся валидным фундаментом (источники/LLM/воронка совпали с картиной мира).
