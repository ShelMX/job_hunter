# UI: сценарии, модели, объём итерации (продуктовое решение от 2026-10-12)

## Чему нас учат аналоги (исследование)

| Решение | Что забираем | Что НЕ забираем |
|---|---|---|
| Huntr / Teal (SaaS) | канбан-воронка откликов, follow-up, заметки, Chrome-save | облако, подписка, ручной ввод |
| JobOps (OSS) | multi-source + трек ответов | Gmail-интеграции |
| Gsync/jobsync (OSS, self-hosted) | таблица+статусы+AI-оценка в одной БД | Next.js-стек — не наш |
| JobHunt (jamerst) | агрегированная лента многих поисков | их модель поиска |
| First2Apply (desktop) | алерты «новых за день», in-app просмотр | Electron |
| Общий паттерн всех: **Inbox → Действие → Воронка** | именно она и есть наша IA | — |

Наши преимущества поверх аналогов (не повторять их): локальность, мультиисточники live, explainable-скоринг, LLM-триаж и вердикты из локальных моделей, история наблюдений (перепосты/«вечные»), скрытие работодателей.

## Главный сценарий (по интервью)

**Утренний дайджест на локальном Mac:** открыть `http://127.0.0.1:8777/` → за ночь фоновый планировщик собрал и триажировал свежее → список уже отранжирован → за 5–10 минут: чтение карточек, ✨ интересно / ✖ скрыть → на интересные откликнуться на сайте источника → вернуться и отметить «откликнулся (дата)» → карточка уходит в воронку.

## IA (страницы)

| Маршрут | Назначение |
|---|---|
| `/` | **Дайджест**: свежее за N дней, без скрытых/скрытых-работодателей/триаж-дропов; быстрые действия в строке |
| `/vacancies` | Вся база: фильтры (текст, источник, дата), пагинация |
| `/vacancies/{id}` | Карточка: поле + описание + скоринг-сигналы + **аналитика** (возраст, перепосты, история, работодатель-сводка, размер кластера) + действия + «проанализировать LLM» (on-demand из кэша или вычислить) + заметка |
| `/pipeline` | Канбан: интересно → откликнулся → ответ/интервью → оффер/отказ (движение кнопками, без DnD в v1) |
| `/clusters` | Группы смежных/дублированных ролей у работадателя (rapidfuzz, пониженный порог) |
| `/employers` | Скрытые работодатели: список + разблокировка |
| `/report` | Полное ранжирование (rules + LLM-кэш) — читалка |
| `/reports/{name}` | md-отчёты из data/reports |

## Модель состояния (миграция 0003)

- `vacancy_states(record_id PK, status, note, applied_at, updated_at)`
- `vacancy_status`: `new → interested | hidden`; `interested → applied → responded → interview → offer | rejected → archived`. `hidden` исключается из дайджеста/листов умолчально.
- `hidden_employers(name PK, created_at)` — работодатель исчезает из всех выдач умолчально.
- Правило дайджеста: `first_seen_at ≥ сегодня−N` И не hidden И работодатель не скрыт И (профиль есть ⇒ триаж ≠ drop).

## Фоновый планировщик (в веб-процессе)

APScheduler (MIT): fetch по пресетам профиля 09:00 и 18:00 (+ триаж новых, если LLM доступен; ресурс-политика §7.1 соблюдается). Конфиг: `settings.yaml.scheduler`. Отключаемо.

## Не делаем сейчас (осознанно)

DnD-канбан (кнопки достаточно), HTMX-live (GET/POST формы), мобильный доступ (приватность), follow-up-напоминания с уведомлениями (v2), multi-user/auth (localhost single-user).

## Критерии приёмки итерации

Дайджест за 1 утренний заход: открыть → увидеть ранжированное свежее → отметить → отклик зафиксирован → в пайплайне виден. Планировщик собирает сам. Тесты web-слоёв зелёные.
