# ADR-0001: Local-first на SQLite вместо серверной БД

- **Дата:** 2026-10-12
- **Статус:** accepted
- **Связанные документы:** PLAN.md §3, PRODUCT.md C1/C5, docs/DISCOVERY.md §6

## Контекст
Приватность — жёсткое требование (C1): профиль, резюме и история поиска не покидают машину владельца. Single-user, localhost (C5). Данные: вакансии, наблюдения, кэш LLM, воронка — десятки тысяч строк максимум.

## Варианты
1. **SQLite-файл** — нулевая инфраструктура, один файл, бэкап = копия файла, Alembic-миграции.
2. Postgres в докере — мощнее (параллелизм, типы), но требует сервиса, паролей, ресурсов ноутбука.
3. Облачная БД — противоречит C1 напрямую.

## Решение
SQLite. Критерий: приватность + простота эксплуатации на Mac + достаточность нагрузки. Доступ абстрагирован репозиториями-портами (`VacancyRepository`, `LLMCache`, `StateRepository`), поэтому переезд на Postgres при появлении реальной необходимости — замена адаптера, не переписывание логики.

## Последствия
- Плюс: бэкап ротацией в `data/backups/` (задача v0.4), никакой сетевой поверхности у БД.
- Минус: нет параллельной записи из нескольких процессов — учитываем (web+scheduler в одном процессе).
- Откат: репозитории уже изолируют SQL; при переезде меняется `infrastructure/db`.
