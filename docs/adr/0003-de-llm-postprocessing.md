# ADR-0003: Де-LLM постпроцессинг текстов отклика (гибрид: правила + второй LLM-проход)

- **Дата:** 2026-10-12
- **Статус:** accepted
- **Связанные документы:** docs/requirements.yaml FR-003, FR-004; docs/DISCOVERY.md §7.5, §7 (F3); docs/PRODUCT.md C3, C4, C7; PLAN.md §7.1, M4 (v0.4.0)

## Контекст
Владелец требует (DISCOVERY §7, §7.5), чтобы черновик письма/подсказок (F3) в v0.4 не выглядел LLM-сгенерированным: без канцелярита, шаблонных тире и оборотов («важно отметить»), с конкретикой из профиля/вакансии и живым ритмом. «Сырой» вывод локальной модели палится чекерами. При этом ресурсная дисциплина (C3, PLAN.md §7.1) запрещает лишние проходы модели и держит ≤1 загруженную модель; лишний LLM-проход тратит RAM/время, а чистая правка правилами не умеет «переписать по-человечески». Реюз-первый принцип (C7) требует сначала поискать готовые списки маркеров/детекторы.

## Варианты
1. **Только правила-чистка** — regex/словари маркеров, удаление шаблонов, правка тире. Плюсы: ноль LLM-ресурсов, детерминированно, тестируемо. Минусы: не умеет перефразировать и варьировать ритм; легко обходится новыми маркерами; текст остаётся «пресным».
2. **Только второй LLM-проход** — «перепиши живее, короче, конкретнее». Плюсы: реально меняет формулировки, добавляет конкретику. Минусы: ещё один вызов на каждый черновик (RAM/время при C3), непредсказуемость, риск новой «роботности», нужен контроль промпта.
3. **Гибрид: правила + второй LLM-проход + опциональный детектор** — сначала дешёвая чистка известных маркеров, затем LLM-перефраз под живой стиль, затем проверка детектором/набором правил. Плюсы: покрывает и удаление маркеров, и перефраз; правила снимают часть работы с модели. Минусы: больше кода и точек отказа; нужен критерий «прошло/нет».
4. **Ничего не делать** — отдать «сырой» текст. Отклоняется: прямо противоречит требованию владельца (DISCOVERY §7.5).

## Решение
Вариант 3 (гибрид), реализующий FR-004. Критерий выбора: требование владельца по качеству (не палиться) + ресурсная дисциплина C3 (правила снимают часть нагрузки, второй проход — один, в общем батче/выгрузке). Порядок: (1) правила-чистка известных маркеров; (2) один LLM-проход «живее/короче/конкретнее» в рамках уже загруженной модели; (3) проверка детектором маркеров (OSS либо свой набор правил) ниже заданного порога. Де-LLM-слой обязателен в штатном F3 и не отключается. Перед кодом — исследование OSS-детекторов/списков маркеров (C7).

## Последствия
- Плюс: финальный текст содержит конкретику и не имеет шаблонных маркеров; слой тестируем (правила — юнит-тестами, порог детектора — на корпусе).
- Минус: +1 LLM-вызов на черновик (учтено в §7.1: батч, конкурентность 1, выгрузка) и зависимость от качества детектора; порог детектора требует калибровки.
- Что теперь нельзя: отдавать владельцу текст без прохождения слоя; обходить C3 (несколько проходов/моделей одновременно).
- Откат: слой изолирован — при непригодности второго прохода его можно заменить на расширенный набор правил без смены интерфейса F3; при снятии требования — уменьшить до правил (вариант 1).
