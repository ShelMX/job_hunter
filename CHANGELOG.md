## [0.3.1] — 2026-10-12 — «Чистота дайджеста»

**Исправлено**
- Дайджест по умолчанию показывает **только LLM-триажированные релевантные** (с профилем); непроверенные — под переключателем `?unvetted=1` со счётчиком. *Почему: владелец справедливо указал, что в дайджест просачивался шум («менеджер по продажам» и т.п.).*
- Страница `/clusters` больше не показывает вакансии, отсеянные триажем, скрытые или скрытых работодателей (была глобальным видом всей базы). *Чейндж демо-мусора:* база очищена от демо-запросов («python»…) и пересобрана под пресеты профиля из резюме.
- **Bug:** ключ кэша триажа отличался от читаемого в дайджесте/планировщике (trailing `|`) → единая функция `_key()` + починка 344 строк кэша. Регрессионный тест добавлен.

**Добавлено**
- CLI `job-hunter triage [--days N] [--limit N]` — триаж свежих непроверенных отдельной командой.
- Планировщик: `triage_pool_limit` 40→300 (tev1 дешёвый ≈1 с/решение — покрываем весь дневной приток).
- Бейджи в дайджесте: ✅ триаж-keep, ⏳ не проверено.
- PRODUCT.md: ограничение C8 (до v1.0.0 данные можно чистить целиком — сервис сырой).

## [0.3.0] — 2026-10-12 — «Продуктовый UI и эксплуатация» (этап M3)

**Что сделано**
- Web UI на localhost (FastAPI + Jinja2, server-side, автоэскейпинг): дайджест за N дней, список с фильтрами, карточка вакансии, воронка откликов, кластеры, работодатели, читалка отчётов.
- Модель состояния: `vacancy_states` (статус/заметка/дата отклика) + `hidden_employers` — миграция 0003.
- Карточка с продольной аналитикой: возраст, span наблюдения, перепост-лаг, размер кластера, сводка по работодателю (дубли, доля «вечных»).
- On-demand LLM-анализ карточки (кнопка «Проанализировать», ресурс-политика соблюдена).
- Планировщик в web-процессе (APScheduler): сбор по пресетам профиля в 09:00 и 18:00 + триаж свежих.
- Действия в UI: интересно/скрыть/отметка ручного отклика/заметки/скрыть и вернуть работодателя.
- Репо-гигиена: `config/profile.yaml` выведен из трекинга, `profile.example.yaml`, .gitignore персонального.

**Почему:** интервью владельца: главный сценарий — утренний дайджест + быстрые отметки; канбан полный; localhost.
**Для чего:** ежедневный обзор за один заход; фиксация откликов без потерь дат и заметок.
**Что изменилось:** появился графический интерфейс и фоновые сборы; CLI остаётся полноценным.
**Качество:** 60 тестов, mypy strict, ruff — зелёные.

## [0.2.0] — 2026-10-12 — «Локальный LLM-слой» (этап M2) *(вошёл в историю вместе с 0.1.0)*

**Что сделано**
- Порты `LLMClient`/`LLMCache`; адаптеры Ollama (нативное `/api/*`; `/v1/systemone` для decision-моделей tev1:4b/clef-flash) и LM Studio; фабрика primary→fallback.
- Ресурсная дисциплина §7.1: тиры моделей по свободной RAM (psutil), ≤1 резидент, батч, выгрузка после батча (`keep_alive=0`, `lms unload`), num_ctx-кап, чужие модели не трогаем.
- Триаж вакансий decision-моделью (вероятность, порог 0.5, fail-open), Экстрактор структуры и Скорер fit 0..5 с объяснением — строгие Pydantic-JSON; кэш `llm_cache` (миграция 0002) — повторные вызовы бесплатны.
- Импорт резюме (md/txt/pdf/docx) в профиль с предпросмотром; CLI `llm`, `report --llm/--no-llm --llm-top`.

**Почему:** владелец требует разумного использования ресурсов MacBook.
**Для чего:** семантический отсев шума и объяснимые вердикты локально, без затрат и утечек.
**Что изменилось:** оценки стали гибридом rules+LLM; отчёт учитывает триаж.

## [0.1.0] — 2026-10-12 — «Каркас и rules-аналитика» (этапы M0+M1, squash)

**Что сделано**
- Clean Architecture: domain/application/infrastructure/connectors/presentation; плагины источников (builtins + entry points); конфиги `connectors.yaml` (вкл/выкл без пересборки).
- Источники: Habr Career (JSON API фронтенда), hh легальный RSS, Trudvsem (официальный открытый API Роструда), SuperJob (бесплатный ключ), RemoteOK (код готов; сеть троттлит — выключен).
- История наблюдений (first/last_seen, times_seen), дедуп и кластеры (rapidfuzz), правила-скоринг с причинами (веса `scoring.yaml`), deal-breakers, отчёт Markdown, профиль-визард.
- CLI: init/sources/fetch/vacancies/report/clusters/profile; политика доступа агента `opencode.jsonc`; SecretStr.

**Почему/для чего:** фундамент расширяемости и приватности; ранжируем от наиболее интересных — уже без LLM.
**Качество:** ruff, mypy strict, pytest — зелёные с первого релиза.
